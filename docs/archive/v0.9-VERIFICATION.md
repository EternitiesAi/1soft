## Observed checks

- All **498 discovered local Python tests passed**, with zero skips/errors/failures, across **16 bounded test processes**. The exact test IDs were reconciled: every discovered ID passed once in that coverage set. This is not a claim that a combined single-process run passed.
- **56** of those cases are new transport/CLI tests. They are not additive to 498. Their HTTP servers run on loopback and are explicitly fixtures, not real CometBFT servers.
- The independent JavaScript budget reference passed its **30 tests**. It remains separate from native transport/accounting.
- The complete required-source inventory matched **58 files**. The independently runnable transport subset declares ten source files in its own inventory; the old full-node inventory is not reduced on GitHub.
- Real process exits before socket access and after receiving an RPC response preserved the pre-I/O dispatch attempt. Restart required explicit replay and retained exact transaction bytes.
- One test applied an actual native transfer in the HTTP fixture, then dropped its reply. The client reported unresolved and subsequently accepted a synthetic signed receipt for the exact payment. This is not distributed consensus.
- An endpoint CheckTx admission never marked the payment settled. Invalid framing, oversized/malformed responses, wrong hashes/IDs, redirects, proxy variables and total-timeout cases were exercised.
- Stored proof corruption and changing a verified status without proof were rejected. A separately crafted synthetic certificate for a different valid signature over the same body was rejected by the exact-envelope binding.

## Failures and unassessed gates

The initial newly authored transport implementation lacked stored-proof verification when reading status. The first test run captured that regression; the implementation was corrected and targeted tests now recheck the certificate and signatures. An initial full baseline run and two broad transport runs exceeded this execution environment's call limits; their incomplete logs are preserved and are not reported as passed. The complete suite was then run in bounded groups with explicit ID reconciliation.

The ordinary Go dependency endpoint still fails DNS in this runtime. The actual network runner returned **unassessed with zero engine steps**, after successfully checking all 58 source files. There is no CometBFT binary or live validator result, and no mock engine has replaced this gate. The previously blocked ABCI transport upload was not retried, encoded, renamed or rerouted.

## Interpretation

This is a real local HTTP submission boundary around signed native transfers, not a verified validator network. There is no signing or custody in the transport. Existing wallet-held funds and signing decisions are not atomically coupled to the transport journal. Its status is not latest account state, a USD claim, a public launch or card/cash settlement. Fixed validator trust, explicit local trust expiry and a trusted local filesystem remain assumptions.
